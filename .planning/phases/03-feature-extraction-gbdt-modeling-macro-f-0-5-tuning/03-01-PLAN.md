<objective>
Implement the 24-dimensional feature extraction engine (`src/features.py`) and pairwise dataset builder with hard negative mining (`src/dataset.py`) for Phase 3.

Purpose:
Downstream LightGBM training requires high-throughput C++ SIMD string distance features, character 3-gram overlap, street number conflict detection, missing metadata indicator flags, and balanced 1:4 positive/hard-negative candidate pair training sets.

Output:
- `src/features.py`: RapidFuzz SIMD metric extractor, char 3-gram calculator, numeric conflict parser, and 24-dimensional vectorizer.
- `src/dataset.py`: Hard negative mining engine selecting non-matching candidates from Phase 2 blocking output, constructing balanced 1:4 training pairs and full validation candidate pairs.
- `tests/test_phase3_features.py`: Comprehensive Pytest suite asserting 24-feature schema, value bounds, street number conflict logic, and dataset generator balance.
- `scripts/verify.ps1`: Updated verification harness running Phase 3 feature and dataset tests.
</objective>

<context>
User locked decisions:
- D-01: Mine hard negatives directly from Phase 2 candidate blocking results for training Source 1 entities (using highest-scoring non-matching candidates from the top-25 pool). Non-candidate random negatives are used only if candidate count is insufficient.
- D-02: Standardize on a 1:4 positive-to-negative training pair ratio.
- D-03: Validation pairs generated without downsampling from official 20% validation split entities to mirror inference candidate distributions.
- D-04: Engineer exactly 24 dense, highly discriminative features across seven logical families:
  1. Name String Similarity (5): RapidFuzz Jaro-Winkler, Levenshtein ratio, Token Sort ratio, Token Set ratio, Token Containment.
  2. Address String Similarity (4): RapidFuzz Jaro-Winkler, Levenshtein ratio, Token Sort ratio, Token Set ratio.
  3. Composite Text Similarity (3): Name + Address concatenated Jaro-Winkler, Levenshtein ratio, Token Jaccard.
  4. Character N-Gram Jaccard (2): Char 3-gram Jaccard on name, Char 3-gram Jaccard on address.
  5. Street Number & Numeric Conflict Detection (3): Extracted digits Jaccard similarity, has_exact_number_match, has_number_conflict penalty flag.
  6. Missing Field & Length Ratio Indicators (5): s1_has_addr, cand_has_addr, both_have_addr, name_len_diff_ratio, addr_len_diff_ratio.
  7. Blocking Prior Signals (2): Blocking similarity score (TF-IDF dot product) and candidate rank index (1 to 25).
- D-05: RapidFuzz C++ SIMD bindings (`rapidfuzz.distance`) must be used for all string metrics to maintain high throughput (>50,000 pair evaluations/sec).
</context>

    2. Implement `extract_name_features(s1_name: str, cand_name: str) -> List[float]`:
       - `name_jw`: `JaroWinkler.similarity(s1_name, cand_name)` (0.0 if either is empty/None).
       - `name_lev`: `Levenshtein.normalized_similarity(s1_name, cand_name)` (0.0 if empty).
       - `name_token_sort`: `fuzz.token_sort_ratio(s1_name, cand_name) / 100.0` (0.0 if empty).
       - `name_token_set`: `fuzz.token_set_ratio(s1_name, cand_name) / 100.0` (0.0 if empty).
       - `name_containment`: Compute token intersection over minimum token count `min(len(s1_toks), len(cand_toks))` (0.0 if empty).
    3. Implement `extract_address_features(s1_addr: str, cand_addr: str) -> List[float]`:
       - `addr_jw`, `addr_lev`, `addr_token_sort`, `addr_token_set` (all normalized to [0.0, 1.0], 0.0 if empty).
    4. Implement `extract_composite_features(s1_name: str, s1_addr: str, cand_name: str, cand_addr: str) -> List[float]`:
       - Concatenate non-empty clean name and address into `s1_combo` and `cand_combo`.
       - `combo_jw`, `combo_lev`, and `combo_token_jaccard` (token intersection over union).
    5. Implement `char_3gram_jaccard(text1: str, text2: str) -> float`:
       - Strip spaces, build set of overlapping 3-character substrings.
       - Return `len(set1 & set2) / len(set1 | set2)` if union is non-empty else `0.0`.
       - Compute `name_char3gram` and `addr_char3gram`.
    6. Ensure strict None, NaN, and empty string safety: all metrics return float 0.0 without throwing exceptions.
  </action>

    Enhance `src/features.py` to complete the 24-feature vector:
    1. Implement street number & numeric conflict detection:
       - Compile `RE_DIGITS = re.compile(r'\b\d+\b')`.
       - Extract numeric tokens `num1 = set(RE_DIGITS.findall(s1_addr))` and `num2 = set(RE_DIGITS.findall(cand_addr))`.
       - `num_jaccard`: `len(num1 & num2) / len(num1 | num2)` if both sets non-empty, else 0.0.
       - `has_exact_number_match`: `1.0` if `num1 and num2 and num1 == num2`, else `0.0`.
       - `has_number_conflict`: `1.0` if `num1 and num2 and num1 != num2`, else `0.0` (flags mismatched house/building numbers on identical street names per FEAT-03).
    2. Implement missing metadata & length ratio indicators:
       - `s1_has_addr`: `1.0` if `s1_addr.strip()` is non-empty, else `0.0`.
       - `cand_has_addr`: `1.0` if `cand_addr.strip()` is non-empty, else `0.0`.
       - `both_have_addr`: `1.0` if both non-empty, else `0.0`.
       - `name_len_diff_ratio`: `abs(len(s1_name) - len(cand_name)) / max(len(s1_name), len(cand_name), 1)`.
       - `addr_len_diff_ratio`: `abs(len(s1_addr) - len(cand_addr)) / max(len(s1_addr), len(cand_addr), 1)`.
    3. Implement blocking priors:
       - `blocking_sim`: Float candidate similarity from Phase 2 blocking output (clipped to `[0.0, 1.0]`).
       - `blocking_rank`: Normalized rank feature: `max(0.0, 1.0 - (float(rank) - 1.0) / 25.0)` where rank 1 maps to 1.0 and rank 25 maps to 0.04.
    4. Implement primary public function `extract_24_features(s1_name, s1_addr, cand_name, cand_addr, blocking_sim=0.0, blocking_rank=1) -> np.ndarray`:

       - Returns a `np.ndarray` of shape `(24,)` with dtype `np.float32`.
    5. Implement batch feature extractor `extract_features_batch(pair_records: List[Dict[str, Any]]) -> np.ndarray`:

       - Exposes `FEATURE_NAMES` tuple of length 24 documenting every column.
